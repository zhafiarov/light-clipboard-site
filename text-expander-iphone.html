Text expander for iPhone: what works without Full Access

A Light Clipboard guide · 20 October 2026

Add a text expander keyboard to an iPhone and Settings will often show a switch called Allow Full Access, with a warning from Apple about everything you type. Some expanders will not run until it is on. Here is what the switch grants, why those keyboards ask, what an expander can do without it, and how to check any keyboard yourself.

What Full Access means

Every third-party keyboard on iOS runs in a sandbox that comes in two versions. In the default one, the keyboard has no network access and can only read what its app saved for it. Apple's developer documentation puts it plainly: without open access, keystrokes cannot be sent to the developer's server or anywhere else.

Full Access is the other version: the developer asks for it, and you grant it with the switch. The warning you see then is Apple's own description of what changes: the developer can now transmit anything you type with that keyboard, including things you typed earlier, such as a card number or a street address. It gains the network and writable shared storage; whether anything is sent is up to the developer.

Why most expander keyboards ask

An expander that only had to type your snippets would not need the switch. The ones that ask usually want it for a feature inside the keyboard itself: sync the keyboard performs on its own, usage counts it records for the app to read later, team libraries, cloud suggestions, crash reports. All of those need the network or writable shared storage.

None of this makes a keyboard that asks dishonest: the warning describes what becomes possible, not what the app does, and a careful developer may need it for a feature you want. But you cannot verify it from outside; with the switch on, you are trusting the privacy policy. Many simple keyboards never ask; the question is whether yours does, and what for.

What an expander can do without it

  • Type your snippets. Inserting text is the one thing every keyboard can do.
  • Read a list the main app saved. The default sandbox allows read-only access to storage shared with the app: the app edits, the keyboard reads.
  • Expand abbreviations as you type them, if it has its own letter keys: a keyboard can see the text around the cursor without Full Access.

What it cannot do: fetch, sync or report anything, or write back to the app. Anything it would need to remember for the app has to move into the app.

How to check any keyboard yourself

  1. Open Settings, then General, then Keyboard, then Keyboards, and tap the keyboard's name.
  2. If you see Allow Full Access, the developer asked for it. If the row is missing, the keyboard cannot get it; iOS enforces that.
  3. Try it with the switch off. If it refuses to work, ask whether you need what the switch unlocks.
  4. Read the App Privacy section on its App Store page.

Questions people ask

What does Allow Full Access mean in Settings?

It is the switch that moves a third-party keyboard out of the default sandbox, where it has no network and can only read what its app saved, into the open one, where it can use the network and share data with its app. It appears only for keyboards whose developers asked for it.

Is Full Access dangerous?

Not by itself. It is a capability; the warning describes what a developer could do with it, not what a given app does. Since you cannot check from outside, it comes down to trusting the developer and needing the feature.

Can a third-party keyboard read my passwords?

iOS shows its own keyboard for password fields, so a custom keyboard never appears there, and apps can block third-party keyboards entirely. Elsewhere, a keyboard with Full Access can in principle send what you type with it; one without cannot.
